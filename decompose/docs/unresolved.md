## UQ-1: Headless Mode Role Enum

**Question:** Should `--role` in headless mode be restricted to an enum (developer, pm, designer, ops, researcher, creator, unspecified) or accept free-form strings?

**Impact:** Error message in `rehydration.md` currently lists accepted values. If free-form is accepted, the error message should be simplified.

**Recommendation:** Accept free-form strings in v1.0 for flexibility; add enum validation in v1.1 once role taxonomy stabilizes.

## UQ-2: Minimum Fixture Golden Coverage

**Question:** PRD requires 9 fixtures with goldens. Only 2 of 9 have complete golden artifact sets (brief.md, genome.json, AGENTS.md) in this build. The remaining 7 have input.md only.

**Impact:** Golden regression eval cannot run on 7 fixtures until goldens are generated by running the skill against each input.

**Recommendation:** Run skill interactively against all 9 fixture inputs, review outputs, and commit as goldens before sealed eval run.

## UQ-3: replay.jsonl Raw Intent Storage

**Question:** PRD says `replay.jsonl` must be sufficient to reconstruct session state, but `raw_intent` must never be in written artifacts. If `raw_intent` contains information lost by redaction, is the replay lossy?

**Impact:** A replay of a redacted session will produce artifacts with `[REDACTED]` markers, not original values. This is correct for safety but may confuse users expecting identical output.

**Recommendation:** Document in SKILL.md that replay is semantically equivalent but may show `[REDACTED]` where redaction occurred. This is a feature, not a bug.

## UQ-4: Parallel Synthesis

**Question:** `task_genome_synthesis` and `markdown_brief` are described as running "in parallel" in the architecture, but in a Markdown-first skill there is no runtime parallelism. Should they be documented as sequential with `brief.md` depending on `genome.json`?

**Impact:** If genome fails validation, brief is also blocked. The current architecture implies brief could be written before genome validation passes — which violates NF-2.

**Recommendation:** Clarify in ARCH.md that "parallel" means conceptually independent (not runtime parallel), and that the Validation Gate blocks both from writing until genome passes.

## UQ-5: Understanding Meter Display for Headless Mode

**Question:** FR-3 (Understanding Meter) applies to interactive sessions. Headless mode skips Steps 1–6. Should headless mode output a final meter value in its artifacts?

**Impact:** `genome.json` includes `meta.meter_pct_at_close`. In headless mode this would be 0 or absent.

**Recommendation:** Set `meter_pct_at_close: null` in headless mode genomes to distinguish from sessions where meter ran.

## UQ-6: Ambiguous Low-Context Fixture Completion

**Question:** The `ambiguous-low-context` fixture has a user who says "I want to do the thing we talked about." The skill cannot proceed to synthesis on this input alone. What is the correct behavior if the user continues to give non-answers through all 7 questions?

**Impact:** The skill must not fabricate a genome based on invented context. But it also must not infinite-loop.

**Recommendation:** After question budget is exhausted with insufficient context, emit a genome with all nodes typed as `unknown`, confidence ≤ 0.4, and surface a message: "I don't have enough information to build a reliable plan. Here is what I'd need to know: [list unknowns]. Please come back once you have more detail."
